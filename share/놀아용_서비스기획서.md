# 놀아용 서비스 기획서

2026년 10월 28일 · 2026 용용톤 여가 생활 및 인프라 트랙

## 요약

용인을 찾는 주말 관광객의 91%가 에버랜드와 민속촌 두 동에만 간다. **놀아용**은 이미 용인에 오는 수도권 가족·커플에게 처인구의 비어 있는 여가 인프라(캠핑장·휴양림·체험마을)를 로컬 점심·디저트와 묶은 AI 하루 코스로 연결한다. 트랙은 여가 생활 및 인프라, 발표는 11/15.

**기획 논리 흐름** (문제 → 원인 → 해결 → 효과)

| 단계 | 내용 | 근거 |
| --- | --- | --- |
| 문제 | 관광객 91%가 에버랜드·민속촌 두 동에 집중, 캠핑장이 모인 원삼·이동·양지는 3% | 경기 행정동간 유입 인구 + 용인시 야영장 현황 |
| 원인 가설 | 발견(정보가 흩어짐) · 조합(한 곳만으로는 부족) · 접근(가는 법 불확실) | 용인시 관광지 데이터 좌표 없음, 블로그 언급량(검증 예정) |
| 해결: 놀아용 | 여가 인프라 장소 DB + AI 하루 코스 조합 + 소요 시간·근거 표시 | 공공데이터 21종 결합, AI 후기 진정성 분류 |
| 기대 효과 | 관광객 분산, 여가 인프라 이용 증가, 처인 로컬 가게 매출 증가 | 측정: 코스 선택·저장 수 (출시 후 지표) |

각 단계 아래는 그 단계를 받치는 데이터다. 아직 검증 전인 항목은 "예정"으로 표시했다.

## 1. 문제: 관광객은 두 곳에만 간다

용인을 찾는 주말 관광객(하루 약 2만 명)의 **91%가 에버랜드(포곡읍)와 한국민속촌(보라동)** 두 동에서 하루를 끝낸다. 캠핑장 51곳 중 31곳이 모인 원삼·이동·양지에는 3%만 간다. 용인의 여가 인프라는 있는데 쓰이지 않는다.

| 사실 | 수치 | 출처 |
| --- | --- | --- |
| 주말 관광 유입 중 포곡읍·보라동 비중 | 49% + 42% = 91% | 경기 행정동간 유입 인구(목적별), 2025년 10월 |
| 원삼면 주말 관광 유입 / 캠핑장 | 하루 518명 / 16곳 | 같은 데이터 + 용인시 야영장 현황 |
| 이동읍·양지면 주말 관광 유입 / 캠핑장 | 집계 없음(소량) / 9·6곳 | 같은 데이터 |
| 용인 캠핑장 중 처인구 | 51곳 중 48곳(94%) | 용인시 야영장 현황 |
| 용인 개방 공공시설 중 처인구 | 97곳 중 65곳(67%) | 경기 공공시설 개방 현황 |
| 구 단위 주말/평일 유입 | 처인 0.89, 기흥 0.91, 수지 0.95 | 경기 시군구간 유입 인구, 12개월 |

**구 단위로 보면 문제가 안 보이고, 행정동 단위로 내려가야 보인다.** 발표에서 "데이터를 파고들어 발견한 문제"로 보여줄 수 있는 지점이다. 한계: 행정동 수치는 한 달(추석 연휴 포함)이고, "집계 없음"은 소량이라 비공개된 값일 수 있다.

## 2. 원인 가설과 검증

원인을 하나로 단정하지 않는다. 세 가지 가설마다 근거와 서비스의 대응 기능을 짝지어, "이 기능은 왜 있나"에 모두 답할 수 있게 한다.

| 가설 | 지금 있는 근거 | 추가 검증 | 서비스의 대응 |
| --- | --- | --- | --- |
| **발견**: 처인의 여가 자원을 알 길이 없다 | 용인시 관광지 데이터 93건에 주소·좌표 없음. 문화행사 38건 중 현재 유효 10건. 농촌테마파크 프로그램 데이터는 2021년에서 멈춤. 경기도 관광농원·법정 관광지 목록에 용인 0건 | 네이버 블로그 언급량: 에버랜드·민속촌 vs 처인 캠핑장·휴양림·체험마을 | 흩어진 공공데이터를 하나의 장소 DB로 합치고 추천에 올린다 |
| **조합**: 한 곳만으로는 멀리 갈 이유가 없다 | 처인 여가 자원은 작고 흩어져 있다(캠핑장이 11개 읍면동에 분산). 대표 시설이 없는 읍면은 관광 유입이 거의 없다 | 시연 코스로 반나절·하루를 채울 수 있는지 확인 | 활동 + 로컬 점심 + 디저트를 동선에 맞춰 묶은 **하루 코스** |
| **접근**: 가는 법이 불확실하다 | 처인구 철도는 에버라인뿐, 신규 철도는 국가계획 반영 요청 단계(2026.10) | 시연 코스의 자차·대중교통 소요 시간 실측 | 코스마다 실제 소요 시간, 주차장, 대중교통이 어려운 곳은 미리 알림 |

**범위 밖**: 시설 자체의 품질, 규제(자연보전권역·팔당), 철도 건설은 서비스로 바꿀 수 없다. 규제는 "새로 짓기 어려우니 있는 것을 연결한다"는 접근의 이유로만 쓴다.

## 3. 사용자와 해결책

타깃은 **이미 용인에 오는 수도권 가족·커플**이다. 주말마다 하루 약 2만 명이 관광 목적으로 용인에 오므로 수요는 이미 있고, 이들의 다음 방문을 두 곳 밖의 여가 인프라로 돌리는 것이 목표다.

| 페르소나 | 상황 | 코스 유형 |
| --- | --- | --- |
| 서울 송파 30대 맞벌이, 6살 아이, 자차 | 에버랜드는 가봤다. 다음 주말엔 덜 붐비는 자연에서 아이가 흙을 만지게 하고 싶다 | **다음 주말의 용인**: 체험마을·휴양림 중심 하루 코스 |
| 수원 20대 커플, 대중교통 | 민속촌에 가는데 오후가 빈다 | **반나절 더하기**: 민속촌 뒤 처인 산책·디저트 반나절 코스 |

처인 주민·소상공인은 사용자가 아니라 수혜자다(방문객·매출·시설 이용률 증가).

**서비스 흐름**

1. 조아용 질문 4개(누구랑·얼마나·어떻게·뭐 하고 싶어) + "용인에서 가 본 곳" 선택(에버랜드·민속촌)
2. AI가 조건에 맞는 코스 3개를 골라 제안: 여가 인프라 중심 활동 + 로컬 점심 + 핫한 디저트
3. 코스 상세: 시간표, 지도, 실제 소요 시간, 주차, 장소마다 추천 근거
4. 대화로 수정: "점심 더 싼 데로", "비 오면?"

**추천 원칙**

- 활동은 여가 인프라에서만 고른다: 캠핑장, 휴양림·수목원, 체험마을, 개방 공공시설, 공공체육시설, 박물관·미술관. 에버랜드·민속촌은 추천하지 않는다.
- 관광 유입이 적은 읍면동의 장소에 가중치를 준다(행정동 유입 데이터). 단, 품질 필터를 통과한 곳만.
- 점심은 처인구 로컬 노포(프랜차이즈·체험단 리뷰 제외), 디저트는 진짜 핫플(협찬 비율 낮은 곳). 둘 다 다음 장소로 가는 길에서 우회 10분 이내.

## 4. 데이터와 AI 활용

데이터는 문제를 찾는 데 한 번, 코스를 만드는 데 한 번 쓴다. AI는 사람이 수작업으로 못 하는 세 곳에만 쓴다.

**데이터 역할** (점검 완료분 기준)

| 역할 | 데이터 | 가공 |
| --- | --- | --- |
| 문제 발견 | 경기 시군구간·행정동간 유입 인구(목적별), 12개월 + 1개월 | 관광 목적만 추려 행정동별 주말 평균, 집중도 계산 |
| 문제 발견 | 용인시 야영장, 경기 공공시설 개방 | 읍면동별 집계 → 관광 유입과 나란히 비교 |
| 코스 재료(활동) | 용인시 야영장·관광지·체육시설·문화행사, 경기 휴양림·수목원·체험마을·개방시설·공원 | 하나의 장소 DB, 좌표 보완(카카오), 행정동 매핑(100m 격자) |
| 코스 재료(식사·디저트) | 경기 일반음식점·제과점 인허가(용인 영업 중 8,712·273곳), 모범음식점, 착한가격업소, 공정위 가맹 브랜드 | 영업 기간·프랜차이즈·인증으로 1차 점수 |
| 추가 수집 | 네이버 블로그 검색 API | 장소별 언급량(발견 가설 검증), 음식점 후기 분류 |
| 이동 | 카카오모빌리티·ODsay, 용인도시공사 주차장 | 실제 소요 시간, 우회 비용 |

**AI가 꼭 필요한 세 곳**

1. **후기 진정성 분류**: 음식점마다 블로그 후기 수십 건을 협찬·리뷰 이벤트·내돈내산·재방문으로 나눠 "진짜 리뷰 수"를 구한다. 휴양림 한 곳 주변에만 후보가 1,089곳이라 사람이 못 한다.
2. **코스 조합**: 동반자·시간·이동 수단·취향을 자연어에서 뽑아내고, 수백 개 장소 중 조건에 맞는 조합을 고른다. 검색·동선은 코드, 조건 이해·선택 이유는 LLM.
3. **설명**: 장소마다 "왜 당신에게 이 곳인가"를 데이터 근거(영업 기간, 진짜 리뷰 수, 인증)와 함께 조아용 말투로 쓴다.

환각 방지: LLM은 장소 ID 목록 안에서만 고르고, 숫자(시간·가격·거리)는 코드가 넣는다. 사람은 음식점 AI 점수 상위 10곳만 사진으로 검수하고, 그 결과를 AI 판정과의 일치율로 발표한다.

## 5. 심사 기준 대응

평가 항목마다 발표에서 내밀 증거를 하나씩 정했다. 동점 기준(데이터 활용 → 문제 정의) 두 항목은 이미 증거가 나왔다.

| 평가 항목 | 핵심 질문 | 우리의 증거 | 상태 |
| --- | --- | --- | --- |
| 문제 정의 & 기획 | 데이터에서 출발했나 | 구 단위로는 안 보이던 문제를 행정동 단위에서 발견(91% 집중) | 확보 |
| 데이터 활용 | 분석·가공, 결합의 깊이 | 유입 데이터 13개월 + 장소·음식점 공공데이터 결합 + 블로그 추가 수집 | 문제 부분 확보, 장소 DB는 개발 중 |
| AI 활용 | 꼭 필요한 곳, API 호출 이상 | 후기 진정성 분류 + 코스 조합 + 근거 있는 설명, AI·사람 일치율 | 설계 완료 |
| 기술 구현 | 안정 동작, 데이터·AI 연결 | 배포 링크 라이브 시연, 외부 API 사전 캐시 | 개발 전 |
| 디자인 & UX | 처음 봐도 이해, 결과가 쉽게 보임 | 버튼 질문 4개, 코스 카드 3개, 추천 근거 배지, 조아용 | 화면 설계 전 |

**트랙 적합성**: 코스의 활동은 여가 인프라(캠핑장·휴양림·체험마을·개방 공공시설)에서만 고르고, 발표의 핵심 단어는 "여가 인프라 활용의 불균형"이다.

**발표 4분 구성**: 문제(두 동 집중 그림, 40초) → 원인 세 가지(30초) → 해결 흐름(40초) → 데이터·AI 파이프라인과 일치율(1분 20초) → 기대 효과와 확장(30초). 시연 2분은 송파 가족 페르소나 하나로.

## 6. MVP 범위와 일정

점수에 직접 닿는 것만 만든다. 배포는 11/9, 발표는 11/15다.

| 기능 | 결정 |
| --- | --- |
| 질문 4개, 검증된 코스 10개 이상 중 요청마다 3개 제안, 코스 상세(시간표·지도·가는 법·근거), 대화 수정 | 만든다 |
| 발표용 "두 동 집중" 지도 | 만든다 (문제 정의의 중심) |
| 코스 저장·공유 링크 | 시간 남으면 |
| 커뮤니티(코스 기록·피드), 날씨 대체, 음식 사진 AI 판별 | 뺀다. 발표의 확장 계획으로만 |

- [ ] ~11/2: 장소 DB(여가 인프라만), 코스 권역 5곳(원삼·이동·양지·모현·백암) × 코스 유형 2개(다음 주말 하루 / 반나절 더하기) = 검증된 코스 10개 이상, 블로그 언급량 검증, API 키 발급, 화면 설계
- [ ] ~11/9: 음식점 AI 필터 + 상위 10곳 사람 검수, 코스 생성 구현, 배포
- [ ] ~11/14: AI·사람 일치율 계산, 시연 캐시·백업 영상, 발표 PDF, 리허설 3회

## 7. 남은 검증과 팀 결정

발표 전에 꼭 닫아야 할 구멍은 두 개다. 하나는 "발견" 가설의 직접 증거이고, 하나는 91%가 한 달의 우연이 아니라는 확인이다.

- [ ] 네이버 블로그 언급량 비교(에버랜드·민속촌 vs 처인 여가 인프라) → "발견" 가설의 직접 근거
- [ ] 행정동 유입을 여름 성수기 1개월 더 집계 → 91% 재현 확인
- [ ] 팀 결정: 역할 분담, 기술 스택·배포, LLM과 예산, 서비스 이름, 코스 권역 5곳 확정
